# 🤖 Auto-Doc-Tool Agent V4.0

**基于三脑协同矩阵 (Macro/Micro/QA) 的通用实验报告智能体自动化生成系统**

Auto-Doc-Tool 是一个零人工干预的智能文档生成引擎。只需上传 Python 实验代码、运行截图与现场日志，系统即可通过本地化部署的大语言模型（Ollama + Qwen2.5:7b），自动提取代码 AST 抽象语法树，并结合自定义 Word 模板，一键生成具有极高学术/工程规范感的 `.docx` 实验报告。

---

## 一、 系统架构图 (System Architecture)

系统采用高度模块化的现代智能体架构，实现了从前端交互到大模型推理，再到确定性排版的端到端闭环。

```text
┌─────────────────────────────────────────────────────────┐
│               1. 交互与通信层 (Gradio Web UI)             │
│  (宽屏自适应 / 卡片式渐进布局 / yield+SSE 毫秒级保活机制)    │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│               2. 预处理与路由层 (AST Parsing)             │
│  (精准解构: import / load_model / core_robot / main)     │
└─┬────────────────────────┬────────────────────────────┬─┘
  ▼                        ▼                            ▼
┌─────────┐            ┌─────────┐                  ┌─────────┐
│ 宏观大脑 │            │ 微观探针 │                  │ QA 智能体│
│ (Macro) │            │ (Micro) │                  │ (QA)    │
│架构与理论│            │AST 级直喂│                  │联调日志解析│
└─────────┘            └─────────┘                  └─────────┘
  │                        │                            │
  └────────────────────────┼────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│               3. 渲染与输出层 (Word Rendering)            │
│ (docxtpl 引擎 / 剥离 AI 排版权 / 代码高亮 / 图片绝对居中)    │
└─────────────────────────────────────────────────────────┘

```

**架构拆解：**

* **交互与通信层**：前端采用 Gradio 深度定制，通过生成器与 SSE 技术实现通信保活，彻底告别长耗时任务导致的“前端超时转圈”断连问题。
* **预处理与路由层**：在 Agent 介入前，提取代码抽象语法树（AST）。动态路由中心 (`build_report_router`) 会根据 Word 模板的占位符需求，将 AST 素材精准分发。
* **核心大脑层 (Three-Brain Matrix)**：
* **宏观大脑 (Macro)**：生成具备学术厚度的系统架构与理论分析。
* **微观探针 (Micro)**：采用“直喂式”策略进行硬核代码审视，杜绝工具链调用报错与大模型幻觉。
* **QA 智能体 (QA)**：深度剖析真实运行日志，提炼现场联调步骤。


* **渲染与输出层**：排版权限全部交还给 `.docx` 模板引擎，Python 端仅负责代码块高亮与格式注入，彻底解决大模型生成文本导致的格式错乱。

## 二、 系统创新点 (Innovations)

本项目不仅是自动化脚本，更在向 2026 年前沿的智能体认知架构演进：

* **基于“三脑协同与共享记忆”的异步架构**：打破传统的单向流水线作业，建立全局记忆池（Context Pool）。不同视角的 Agent（宏观/微观）不再各说各话，而是基于统一的黑板记忆进行交叉验证，消灭上下文逻辑割裂。
* **Actor-Critic 自我反思闭环**：通过分离“生成者（Actor）”与“审查者（Critic）”，利用多智能体对抗机制。强制约束大模型的大白话输出，打回一切不符合被动语态、学术专业术语的段落并重写，保障输出结果严格符合学术级论文标准。
* **代码逻辑拓扑感知 (向 GraphRAG 演进)**：超越零散代码块的“盲人摸象”，通过 AST 提取代码上下文调用链。让 Agent 在解析函数时，能立体感知该模块的输入来源与输出去向。

## 三、 系统的实际测试效果 (System Performance)

经过实际业务工程验证，系统达到了以下生成标准：

* **零幻觉硬核解析**：依托 AST 精准切片与直喂式探针，AI 在代码解析环节做到了 100% 引用真实类名、变量名与函数库，彻底杜绝了胡编乱造的函数调用。
* **极致的学术质感**：得益于 Actor-Critic 双重审查机制，最终报告中“极大提高了效率”、“完美实现了功能”等 AI 营销味废话被完全抹除，全部替换为客观的第三人称陈述与被动语态。
* **硬核现场联调还原**：QA 智能体能从运行日志中精准抓取带时间戳的具体参数（如舵机角度、坐标系等），并生成极具现场画面感的测试步骤。
* **Word 格式绝对稳定**：成功隔离了 LLM 的排版干扰（如乱用 Markdown 标记），生成的 `.docx` 文件格式严整，代码块缩进正常，图片完全居中，实现真正意义上的“开箱即用”。

## 四、 复现需要的准备 (Quick Start & Deployment)

本项目采用**算力端分离 (C/S)** 的设计理念。Linux 容器作为“云端大脑”提供大模型算力，Windows 客户端作为“UI 躯壳”提供开箱即用的前端交互。

### 1. 环境依赖与版本锁定

如果你需要在本地直接运行调试，请严格安装以下 Python 依赖。**注意：必须锁定版本以规避 Pydantic v1/v2 的底层冲突。**

```bash
pip install "crewai==0.41.1" "langchain>=0.2.0,<0.3.0" "gradio" "docxtpl" "python-docx"

```

### 2. 模型与云端算力节点准备 (Linux/Server)

系统默认使用 Ollama 驱动本地 Qwen2.5:7b 模型。你需要在服务端配置 Ollama 并暴露固定公网 API。

* **启动 Ollama 服务 (允许外部访问)**：
```bash
export OLLAMA_HOST=0.0.0.0
nohup ollama serve > ollama.log 2>&1 &

```


* **配置 Ngrok 内网穿透 (保持通信永不掉线)**：
前往 Ngrok 官网免费申领一个固定静态域名，并在服务器后台静默打洞：
```bash
nohup ngrok http --domain=your-domain.ngrok-free.app 11434 --log=stdout > ngrok.log 2>&1 &

```


* **更新通信域名**：
将 `auto_tool.py` 源码中所有的 API 请求地址（`[http://127.0.0.1:11434](http://127.0.0.1:11434)`）替换为你的 Ngrok 固定域名接口。

### 3. 客户端打包与启动 (Windows EXE)

项目内置了 GitHub Actions 流水线，代码推送即可自动生成 Windows 可执行程序。

* **必备模板文件**：打包或运行前，请务必确认根目录下存在核心模板资产（`template_complex.docx` 和 `template_simple.docx`），否则系统在路由时会报错。
```bash
git add -f template_complex.docx
git add -f template_simple.docx

```


* **获取与运行免安装客户端**：
在 GitHub 仓库的 **Actions** 页面下载自动构建的 `Auto-Doc-Tool-Windows-Release.zip`。解压后双击 `.exe` 即可弹出 Web UI，实现“零配置、秒出报告”。
* **本地 Python 直接启动**：
确保本地 Ollama 正在运行后，直接执行：
```bash
python web_ui.py

```
